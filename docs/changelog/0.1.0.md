# 0.1.0

_2026-09-18._ The first extraction, from the National Geographic _Food for
Tomorrow_ globe.

[Compare on GitHub](https://github.com/fndvit/VizVit-Map/commits/main)

## Added

- **A map engine with a provider seam.** One live view behind five ports —
  `camera`, `screen`, `events`, `scene`, `layers` — plus a typed `native(kind)`
  escape hatch for work that is genuinely SDK-bound. A feature written against
  the ports runs on any adapter without being rewritten.
- **Three adapters.** ArcGIS (`SceneView` / `MapView`), MapLibre GL in globe
  projection, and an in-memory fake published at `/testing` so a consumer can
  test its own capabilities without standing up a map SDK.
- **`<Globe>`, configured by one object.** Each feature is a **capability**
  enabled by the presence of its sub-config, never by a flag. The library ships
  markers, cursor hover, pins and outlines; a host adds its own through
  `GlobeConfig.capabilities` and `declare module`.
- **A provider gate.** A capability may declare `requires: 'arcgis'`, and the
  registry refuses to mount it on another provider _before any setup runs_,
  rather than rendering an empty map.
- **PMTiles streaming** at `/tiles`, with a `TileSink` seam that carries neutral
  cells rather than SDK graphics.
- **Fifteen entry points**, so a leaf component can import the one symbol it
  needs without pulling the whole graph. See
  [the reference](../reference.md).

## Notes for consumers

- `@arcgis/core` and `maplibre-gl` are **optional peers**: install only the
  provider you use.
- **Scale, not zoom, is the level-of-detail currency** (1:N at the view centre,
  `0` = unbounded). Providers that think in zoom convert internally, so a tuned
  ladder survives a provider change.
- **Your app owns basemap ids.** The engine knows none; it calls a
  `BasemapCatalog` you supply.
- The MapLibre adapter has documented fidelity gaps — camera altitude is derived
  from zoom, `placement` has no z-order meaning, `setGround` is a no-op, and an
  ArcGIS `well-known` basemap id throws. See
  [Providers](../providers.md#known-gaps-in-the-maplibre-adapter).
