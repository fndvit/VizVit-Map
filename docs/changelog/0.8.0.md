# 0.8.0

_2026-10-05._ Focus. A globe can now say which one area it is about. `GlobeConfig.focus` names a region, the `outlines` capability draws its outline, and every capability listed in `focus.confine` confines itself to it. The package's `markers` and `pins` honour it, and a host capability opts in the same way through `focusRegionFor` in its rule. So "the story's region" is declared once instead of being repeated as outlines, label regions and filters. `LayerHandle.setRegion` (0.7.0) gets its first consumer here. Nothing changes for an existing config.

[Compare `v0.7.0...v0.8.0` on GitHub](https://github.com/fndvit/VizVit-Map/compare/v0.7.0...v0.8.0)

## Added

- **`GlobeConfig.focus`** (`region`, `outline`, `visible`, `confine`). The focus outline is drawn by `outlines` as one more outline keyed by the region id, so `outlines` is now active on a `focus` alone. An authored outline with the same id is replaced rather than drawn twice. `outline: false` confines without drawing anything, and `region: null` keeps the capability mounted with nothing focused.
- **`focusRegionFor(config, name)`** (root and `…/capability`): the region for a capability that `confine` names, read in a rule's `select`, so capabilities stay independent of each other. **`createFocusRegionTracker(onShape)`** loads the shape once per region id and drops a superseded one.
- **`markers` and `pins` confine to the focus** when `confine` lists them. `markers` confines through `LayerHandle.setRegion`. `pins`, which is DOM-projected, filters the items it projects.
- **A `confine` name that no mounted capability answers to is warned about** when the globe resolves its capabilities, so a typo no longer fails silently.
- **`regionCenter(shape)`** in `…/geo`: the centre of a region's bounding box, centred across ±180° for a wrapping one. It is where a camera aims to frame a region.

## Changed

- **`outlines` restyles a live outline whose stroke changed.** Before, a new colour or width was ignored until the outline remounted.
